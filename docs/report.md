# 機械学習を活用した日本語命令によるロボット操作

## 1. 概要

日本語の短い命令を機械学習で分類し、シミュレーション上の車輪型ロボットを動かすシステムを作った。対応する動作は前進、後退、左旋回、右旋回、停止の5つである。分類できない命令ではロボットを動かさない。

目的は、言語による指示とロボットの速度制御を、ROS 2 と Gazebo の既存環境のうえで最小限の構成でつなぐことである。

## 2. システム構成

利用者は端末に日本語を入力する。プログラムは文を分類し、結果に応じた `geometry_msgs/msg/Twist` を `/model/vehicle_blue/cmd_vel` へ送る。`ros_gz_bridge` がこの指令を Gazebo の `gz.msgs.Twist` に渡す。ロボットは公式デモ `ros_gz_sim_demos` の `diff_drive` ワールドに含まれる青い差動二輪である。ロボットモデルは自作していない。

処理の順序は次のとおりである。

1. 空入力、左右や前後の同時指定、逆接を拒否する。
2. 文字 n-gram の TF-IDF とロジスティック回帰で分類する。
3. 動作クラスであり、かつ校正データから決めた閾値を超えたときだけ速度を送る。
4. 約2秒後、中断時、終了時、例外時に停止指令を送る。

「少し」「ゆっくり」といった語は、速度や距離を変えない。速度は並進 0.4 m/s、旋回 0.8 rad/s に固定し、公式モデルの上限（並進 0.5 m/s、旋回 1 rad/s）を超えない。左右は並進速度を出さず、その場で旋回する。

## 3. AIモデル

使用ライブラリは scikit-learn である。モデルは次のパイプラインで、プログラム起動時に CSV から学習する。

- `TfidfVectorizer(analyzer="char", ngram_range=(1, 3))`
- `LogisticRegression(max_iter=1000, random_state=0)`

学習データは動作5クラスがそれぞれ30件以上で、合計は forward 32、backward 34、left 32、right 32、stop 34 である。同じ文の繰り返しは使っていない。

文字 n-gram は「名前」に含まれる「前」のように、動作と関係ない文字へ反応することがある。そのため、挨拶、質問、名前や前回を含む文、複数の動作が混ざった文を `unknown` クラスとして46件学習し、このクラスのときは動かさない。unknown はロボットの動作ではなく、拒否のためのクラスである。

`predict_proba` の出力は校正済みの正解確率ではない。拒否判定では、最大クラスの出力スコアと、1位と2位の差（マージン）を使う。閾値は学習データではなく、別の校正データ60件（動作40、拒否20）から決めた。動作クラスへ誤って寄った校正例の最大値と、正しく分類できた校正例の中央値の中間である。実測の閾値は、出力スコア 0.391480、マージン 0.158897 である。

## 4. 評価

評価文58件は学習にも閾値決定にも使っていない。

動作を期待する40件では、受理かつ正解が33件（0.8250）だった。残る7件は拒否され、期待と違う方向へは動いていない。拒否を期待する18件は18件とも不受理だった。

課題確認用の10文はすべて未学習であり、すべて期待どおりに受理された。

| 命令 | 結果 | 出力スコア | マージン |
|---|---|---:|---:|
| 前に進め | forward | 0.4955 | 0.2739 |
| まっすぐ進んで | forward | 0.4347 | 0.2424 |
| 後退してください | backward | 0.4605 | 0.3336 |
| 後ろに下がれ | backward | 0.6074 | 0.4561 |
| 左に曲がって | left | 0.6602 | 0.5337 |
| 左折してください | left | 0.4878 | 0.3262 |
| 右に回転して | right | 0.5133 | 0.3641 |
| 右折して | right | 0.5456 | 0.4171 |
| 止まって | stop | 0.7663 | 0.6839 |
| 停止してください | stop | 0.6026 | 0.5046 |

閾値または unknown により動かさなかった動作寄りの文は、「直進してください」「正面に移動して」「前へ進み続けて」「後進をお願いします」「左回転してください」「動作を止めてください」「動かずにいて」である。このうち「動かずにいて」の第1候補は unknown で、他の6件は第1候補自体は期待クラスだった。

「進め、ただし止まれ」は出力スコア 0.4530、マージン 0.2322 で、数値だけ見ると動作閾値を超える。逆接が含まれるため規則で拒否した。「前か後ろに動いて」もスコア 0.4135、マージン 0.1828 で閾値を超えるが、前後が同時にあるため拒否した。スコアの高さだけで動かすと、これらの曖昧な文を実行してしまう。

## 5. シミュレータでの動作

Gazebo の `diff_drive` 上で、青いロボットのオドメトリを計測した。画面の目視は行っておらず、判断は `/model/vehicle_blue/odometry` の変位である。

- 「前に進め」で車体前方へ 0.758 m 動き、その後の変位は 0.000 m だった。
- 「後ろに下がれ」で車体前方へ -0.749 m だった。
- 「左に曲がって」ではその場で左へ回り、yaw が +1.570 rad 変化した。
- 「右折して」ではその場で右へ回り、yaw が -1.491 rad 変化した。
- 前進を 0.4 秒で中断したときの変位は 0.159 m で、中断後の変位は 0.000 m だった。
- 「こんにちは」では変位 0.000 m、yaw 変化 0.000 rad だった。

各動作のあとには停止指令を送っている。終了時と例外時にも停止指令を送る実装にしている。

## 6. 工夫した点

公式サンプルの起動は Gazebo とブリッジに限定し、日本語の解釈と速度の送り方は独自に実装した。未知の文を無理に5クラスへ入れず、unknown と、校正データに基づく閾値と、複数意図を止める規則を重ねた。出力値を正解確率とは書いていない。

## 7. 制限事項

移動時間と速度は固定である。障害物回避、経路計画、実機制御は行っていない。緑のロボットは対象外である。学習例から離れた自然な言い回しの一部は、安全側に倒して拒否する。

## 8. 再現手順

ROS 2 Jazzy と Gazebo を読み込んだ仮想環境で、`./scripts/start_gazebo.sh` のあと `./scripts/run_robot.sh` を実行する。詳細はリポジトリの README に記載した。
